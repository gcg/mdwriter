## 7. Topics no report covered (or covered too thinly) that the plan needs

1. **Scroll room / typewriter implementation that survives TextView's padding clip** (A15): needs a small emulator experiment task before the editor tasks depend on it.
2. **Find (and replace) in the editor**: platform lists a find bar in the Back order and design lists Find in the overflow, but nobody specified the match highlighting (spans vs an onDraw overlay like Focus Mode), search off the main thread for 300k docs, or next/previous navigation with `bringPointIntoView`.
3. **Export / print**: markdown says the same HTML serves export and print; build asks for an in-app "Export all notes" zip (the only release-data backup path). Nobody specified `ACTION_CREATE_DOCUMENT` zip writing, `PrintManager` + `WebView.createPrintDocumentAdapter`, or HTML/PDF export UX.
4. **Instrumented test infrastructure**: editor-engine requires an instrumented layout-equality test and IME tests, but `Makefile.final` has no `connectedAndroidTest` target and toolchain has no androidTest dependency/runner decision for the editor (only unit/Robolectric/Compose-test notes). Add `make test-device` (`./gradlew :app:connectedDebugAndroidTest`) and a test-runner decision.
5. **IME composition behaviour with MdEditable** (Gboard autocorrect, glide, voice, Samsung Keyboard): flagged as a risk by editor-engine and markdown, but no concrete test protocol. Also `Editor.SpanController` (a SpanWatcher for SuggestionSpan/EasyEditSpan popups) is subject to MdEditable's suppression for shifted spans: needs a check that suggestion popups still work after edits above them.
6. **RTL / bidi paragraphs** in the hang-margin and list-indent scheme (negative leading margins in RTL paragraphs, `getLeadingMargin` side), plus CJK line breaking with `BREAK_STRATEGY_SIMPLE`.
7. **Runtime theme / font / size change path for spans**: editor-engine item 7 mentions a shared mutable `EditorStyle` + one full reflow; the plan needs this explicitly, because `configChanges` includes `uiMode` (no recreation) and span colours are otherwise baked in.
8. **`configChanges` omits `fontScale`, `locale`, `layoutDirection`, `fontWeightAdjustment`** (platform 10.6 list): these still recreate the activity, so the plan needs a restore path test for them (EditText has `isSaveEnabled=false`).
9. **Large-document open UX**: editor-engine measured 0.7-1.0 s to open 300k on the main thread; nobody designed the loading state (placeholder, progress, read-only threshold) beyond platform 2.12's unverified thresholds.
10. **Accessibility of the custom toolbar overlay and swipe gesture** beyond platform 10.2 notes (TalkBack focus order, custom accessibility actions for "Open library", toolbar content descriptions).
11. **Real-device performance validation task** (all numbers are from an Apple-silicon emulator or desktop JVM): markdown and editor-engine both ask for it; the plan should schedule it early.
12. **Baseline profile generation** is deferred by platform/toolchain; if adopted, the Makefile and `installRelease` flow must still work without the `:baselineprofile` module present.
